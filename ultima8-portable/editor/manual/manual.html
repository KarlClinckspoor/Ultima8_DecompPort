U8 Editor Manual

u8edit edits Ultima VIII's world: where every item is, what it is, what eggs do, the characters' numbers, the story's flags, and the weapon, armour and monster tables. It reads and writes the game's own files the way the game does, so what it saves plays in DOS U8.EXE as well as in the port.

What this manual says about the game comes from the decompiled game (source/ and ultima8-portable/game/). Where it is an inference rather than something the code plainly does, it is written in brown; point at a brown passage for why it is not certain.

1. Getting started

Work on a copy of the game folder. Saving writes into the folder that is open; the first time a file is written, its original is kept beside it as name.orig.

File > Open Game Folder opens a folder holding STATIC and USECODE (for the GOG release, the ENGLISH folder). The editor opens the starting saved game, SAVEGAME/U8SAVE.000, which every new game starts from; File > Open Saved Game opens another, and File > Open the Game in Progress opens GAMEDAT, the game the DOS version continues.

Pick a map in the Maps list. File > Save (Ctrl+S) writes what changed, Edit > Undo and Redo take changes back, and File > Test in the Port (F5) saves and starts the port on a new game made from what was saved.

2. The window

  • Maps (left): every map with items, how many, how many teleport eggs lead out, and the named people standing on it. Double-click a name, or press F2, to name a map.
  • Minimap (left): the whole map with the part the view shows; teleport eggs in orange (sending) and green (receiving). Click or drag to move there.
  • Map (middle): the map drawn as the game draws it.
  • Transitions: the maps as a graph of the ways between them.
  • Game Data: weapons, armour, monsters and the characters' numbers.
  • Flags: the story's global flags.
  • Shapes and Search (right): every shape, to place; and the search.
  • Item (Ctrl+I): everything about the selected item; its Edit tab changes it. It is a dock like the others: drag its title bar to put it elsewhere, or out of the window; double-click the title bar to float it or dock it again.
  • Usecode (Ctrl+U): the game's scripts, class by class (The usecode).

Where the docks are, and whether they float, is kept when the editor closes. View > Reset the Layout puts them back where they start.

The toolbars: Save, Undo and Redo; the layers (Fixed, Globs, Movable, NPCs, Eggs, Egg Ranges, Labels, Invisible, Heights); Roof below; Snap; Opacity; and X-ray with its height, radius and Fade.

4. Selecting: piles, boxes and lists

A click takes the topmost item drawn under the pointer. Items buried in a pile, or hidden behind a wall, are easier to reach with a right-click: it lists every item drawn at the pointer, the topmost first, then those drawn within a few pixels of it, each with its picture, name, shape and frame and position. Pointing at an entry highlights the item on the map in magenta (with its bottom and top); choosing it selects it, and choosing it with Ctrl held adds it to the selection. Select All of These takes the whole list. The tooltip of each entry says what the item is.

Several items can be selected at once (Ctrl+click, Ctrl+drag, Ctrl+A, or the list). The primary one, outlined in yellow, is the one the Item window shows; the others are outlined in amber. Moving, Delete, Ctrl+D, F and [ ] then apply to all of them, each as one step to undo. Items the editor cannot change (glob items, for example) are left as they are, and the status bar says why.

5. Moving items exactly

Positions are in world units. On the ground a footpad step is 32 units in x and y; heights go in units of 8 for a shape's size. The Snap box sets the step for dragging, Ctrl+arrows and placing (a floor tile is 128 or 256).

For small moves: Alt+arrows (1 unit in x or y), Shift or Alt with Page Up/Down (1 unit in z), Alt+drag (no snap), or the Item window's Nudge box, whose buttons move by the step chosen (1 to 64) and repeat while held. All of these move every selected item.

The world's x grows down and to the right on the screen, y down and to the left, z up. An item's position is the corner of its footpad nearest the viewer, at its bottom.

6. Seeing inside: roof, opacity, X-ray, heights

  • Layers: Fixed, Globs, Movable and NPCs show and hide items by where they come from; Eggs shows the eggs and the other shapes only an editor shows; Invisible shows items with the invisible flag, faintly.
  • Roof below hides what is at or above a height, except shapes marked to be always drawn, as the game does when the Avatar is inside a building (see How the game draws the world). Try 40 or so inside houses.
  • Opacity has a slider for each layer, to see through walls and roofs everywhere.
  • X-ray (X) works in a circle around the pointer: what is at or above the height set beside it is faded there. Fade sets how much of each layer still shows inside the circle, as Opacity does for the whole map; at the left, a layer is left out. A click inside the circle passes over what is faded, so what is underneath can be picked.
  • Heights (H) draws the bottom (blue) and top (orange) of the selected items and of the item under the pointer, labelled with their heights. The top is z plus the shape's height.

7. Names

An item's name is what the game says when the Avatar looks at it: the editor runs the item's look routine from the usecode in a small copy of the game's usecode interpreter, against the item's quality and frame and the saved game's flags. So a key says which door it opens, and a person is named by what the story so far lets the Avatar know.

View > Full Names (on by default) runs the routine with every flag set instead, so Devon is "Devon" from the start rather than "man". With every flag set, a routine that looks for one particular value of a flag may take a different branch; the tooltip and the Item window also give the name in the open saved game when it differs.

Items whose usecode has no look routine (most scenery) go by the name given to their shape in the Item window's Name box, else by their usecode class made readable ("DOOR_NS" is "door ns"). Map and shape names are kept in the editor's settings; File > Export Names and Import Names write and read them as a text file of map 5 = name and shape 82 = name lines, to share with a mod.

9. Teleport eggs and the ways between maps

A teleport egg of frame 0 sends the Avatar; one of frame 1 receives. A sender sends to the receiving egg with the same teleport id on the map its mapNum names (see Eggs). Egg labels on the map say where each leads ("→ here #3", or "→ 5 · Name #3"). Hovering over a teleport egg, or selecting it, draws an orange arrow to where it leads on the same map, or from the eggs that lead to it; the same holds for usecode that teleports to an egg with constant arguments.

In the Item window a sending egg has Go to destination; a receiving egg has Go to sender, a menu when several eggs or scripts lead to it. The Transitions tab draws all the ways between maps.

10. Doors and keys

The keyring's use routine (usecode class KEYRING, 79, which KEY 82 also runs) decides what a key opens: a key opens a door (DOOR_NS 68, DOOR_EW 69, TDOOR_NS 340, TDOOR_EW 342) when the low byte of the door's quality is the key's quality. In the door's quality, bit 0x400 is the lock, and bit 0x100 is tested as "it's open". A key of quality 0 is a blank.

Using a fitting key turns the lock bit on or off. A key's Item window lists the doors it opens anywhere in the game; a door's lists its keys (and who or what holds them), and its Edit tab has its key number, Locked and Open. On the map, selecting a key outlines its doors in cyan, and selecting a door outlines its keys or what holds them. Find key N searches for both.

11. The Item window

The Edit tab changes the selected item. Its groups depend on the item: what it does as an egg, a door or a key; its Name; its record (position, shape, frame, quality, npcNum, mapNum, flags); Nudge; and for a character, its numbers. Every field has a tooltip. When several items are selected, the note at the top says so: moves, Copy, Delete and flipping apply to all of them, the fields only to this one.

The Details tab shows everything about the item, with links (double-click) to its container, glob egg, contents, transitions, doors and keys, and, under Usecode, to the routine of each event its class handles. Usecode (beside Show on map) opens the class the item runs in the Usecode tab; a monster egg's monster shape leads to the monster's class.

12. Fields and what they mean

Every item on a map is a 16-byte record (OneItem, item/glob.h): the same in FIXED.DAT, NONFIXED.DAT and the saved game's item cache.

FieldMeaning
x, yWorld units: 32 to a footpad cell, 512 to a region, 64 by 64 regions to a map. The position is the item's far corner in x and y and its bottom in z: it covers x−size+1 to x, y−size+1 to y, z to z+height−1. On the screen that corner is the lowest point of the item. A negative value (as a signed 16-bit number) makes the game skip the item when it loads.
zHeight, 0 to 250. 251 (0xFB) and up means out of play, and the game skips such an item when it loads; 254 marks a free slot.
shape, frameThe shape (below 2048) and which of its pictures. The shape decides the type flags and the usecode class. Usecode often keeps an item's state in its frame.
flagsThe status bits (below).
qualityWhat it means depends on the family (Families): a quantity, a key number, a glob number, an egg's settings.
npcNum, mapNumEggs keep their hatch range and id here (Eggs). An NPC's mapNum is the map it is on. On other maps an item with npcNum 255 is refused as bad. For ordinary items the engine ignores both, and they are normally 0.
nextA link the game keeps in memory, written as it is and ignored when loading.

Contained items follow their container in the file. Their x is how deep they are (1 is directly inside), their y the place in the container's window (low byte x, at most 127; high byte y; 0,0 picks a place at random), and z the equipment slot when the item is equipped by a character, else 0.

Status flags

BitNameWhat it does
0x0002disposablenever saved; items put down by glob eggs have it
0x0004ownedmoving an item without it tells every character within 640 units that the Avatar stole something (usecode event 19); it is set once the item is in the Avatar's inventory
0x0008containedinside a container or a character
0x0010invisiblenot drawn in the game (except the Avatar); takes no room in a container; monsters cannot target it
0x0020flippeddrawn mirrored, its x and y sizes swapped
0x0040in NPC lista character kept off the map

0x0200equippedworn or wielded; its z is the slot

The other bits (0x0001, 0x0100, 0x0400, 0x2000, 0x8000) are the game's bookkeeping while it runs, cleared when it saves or loads. 0x0800 (ethereal) marks an item being moved and should not appear in files.

13. Shape type flags

TYPEFLAG.DAT holds 8 bytes for each shape (item/type.h). The Details tab lists them.

15. Eggs

Hatching. An egg's npcNum holds its range: the high nibble in x, the low in y, each in steps of 32 units on each side of the egg. The Avatar is inside when his footpad meets that box and his height is within 48 of the egg's. The egg hatches when he comes in, and again only after he has left. Only usecode eggs and sending teleport eggs hatch by themselves; their watcher starts when their region starts running, so an egg the Avatar stands in when it loads hatches at once. The editor draws the ranges (Egg Ranges).

Teleport eggs (family 8). Frame 0 sends: to the map its mapNum names, to the egg whose teleport id (quality's low byte) is the same, fading the screen when the quality's high byte is not 0. The game looks over the whole destination map for a frame-1 teleport egg with that id, puts the Avatar there and lets him fall; with no such egg he stays where he was. Frame-1 eggs only receive.

Monster eggs (family 7, shape 500). Quality bits 0–10 are the monster's shape, bits 11 and up the probability; npcNum bits 0–2 the count; mapNum bits 0–2 the activity and bits 3–7 the monster id.

  • A monster egg never hatches by itself: a usecode egg hatches it. MONEGG (class 1155, egg type 4) hatches, when it hatches, the monster eggs near it whose monster id is its own egg id, and removes those whose frame is not 0 (they hatch once). MONFAST (class 1213, egg type 62) does the same when its area starts running. Both fire once a visit. They look within about 112 units.
  • The probability picks the chance it hatches: 0 to 7 are 5, 10, 20, 35, 50, 65, 80 and 100 percent. Higher values read past the game's table, so the editor allows only 0 to 7.
  • The count is how many come (0: none). The first stands on the egg, with no check for room; the others on the first free places of a 4 by 4 grid around it, 64 units apart.
  • The activity is what they do: 0 loiter, 1 fight, 2 stand. Any other value halts the game, so the editor allows only 0 to 2.
  • Their numbers are rolled from the monster table (tables); a shape not in the table gets record 0, which has no hit points.

Usecode eggs (family 4, shape 73). They run usecode class 1151 + quality: event 7 when they hatch, and 15 and 16 when their area starts and stops running. (Shape 73 must then be marked noisy.) Their egg id (mapNum) is for the script to read. LOCKDOOR (1210), for example, locks or unlocks the doors near it by its egg id and the story's flags; MAPTELE (1152) teleports when conditions are met.

Glob eggs (family 3). Their quality is a record of GLOB.FLX: a list of items (x, y, z, shape, frame). Only the 512 by 512 region holding the egg counts: each item goes at the region's corner + 1 + 2 × its x (and y), and at its z + the egg's z. The items are put down each time the region starts running and taken away when it stops; they are never saved. To change them, change, move or delete the egg, or pick another glob.

16. How the game draws the world

Projection. A point at x, y, z is drawn at screen x = x/4 − y/4, screen y = x/8 + y/8 − z: 32 units in x is 8 pixels right and 4 down, one unit of height one pixel up. An item's position is the lowest point of its box on the screen.

Order. Of two overlapping items, the game draws over the other the one that is wholly beyond it in x, else in y, else wholly above it; then one with the unknown1 flag; then the one with the larger (x − size x) + (y − size y) + 2z (DL_ItemNode::compare). The editor sorts the same way.

Roof. When the Avatar moves, the game sweeps his footpad straight up and takes the height of the first item with the roof flag it meets (250 when there is none). Items at or above that height are not drawn unless they have the draw flag. The editor's Roof below does the same with a height you choose.

Running area. The game loads a whole map at once (up to about 8960 items, globs put down included; more halts it), but runs only the 512-unit regions in a diamond around the camera: 49 regions. Only there are eggs watched, globs put down, items animated and drawn, and fast-only items kept. On the screen that is about 384 pixels each side and 448 up and down.

17. Characters

NPCDATA.DAT in the saved game holds 49 bytes for each of 256 characters; the Item window and Game Data show them.

  • Strength, dexterity, intelligence, hit points and mana. Most hit points are 2 × strength and most mana 2 × intelligence, worked out rather than stored. Strength × 40 is what a character carries.
  • Alignment: the low nibble is the character's own, the high nibble the alignments it treats as enemies (one is an enemy of another when its high nibble shares a bit with the other's low nibble). Monsters take theirs from the monster table.
  • Invincible and immortal: either keeps hit points from going down. Usecode can set only immortal; invincible is set only by a debugging key. No other difference was found.
  • Withstands death: a blow that would kill restores hit points to 2 × strength once, then the flag clears. Skeletons not killed by fire get it again when they die, and get up.
  • Dead: the character does nothing when its area starts running, keeps no schedule, and using it opens what it carries.
  • Poisoned: nothing in the game sets it.

A character's mapNum is the map it is on; map 0's records are the characters in their slots (1 to 255). Their usecode class is 1024 + their number, except temporary ones (fast only), whose class is their shape.

18. Weapons, armour and monsters

These are not in any data file but in tables inside U8.EXE; the editor changes only their bytes, so DOS U8.EXE plays with the new numbers, and the port reads the same tables from U8.EXE.

  • Weapons: a hit by the Avatar does strength / 5 + base damage + a random 0 to the modifier. The dexterity bonuses are added to attack and defence, and the armour class bonus counts when the weapon is held. Damage type bits: 1 normal, 2 blade, 4 blunt, 8 fire, 0x10 undead, 0x20 magic, 0x40 slayer, 0x80 pierce, 0x100 falling.
  • Armour: the Avatar's armour class is the sum over what he wears. Each piece adds the number at index frame / 2 of its shape's list, so frames 2n and 2n+1 share a number. Wearing any other shape in those slots, or a frame past the end of its list, halts the game.
  • Monsters: 13 bytes each: least and most hit points, dexterity and damage; armour class; alignment (own and enemies); a flag byte (bit 0: wanders one time in ten in combat); the damage types it deals and those it defends against. Hit points and dexterity are rolled once when the monster is made; each blow's damage between its least and most. Record 0 is for shapes not in the table.

The starting save, U8SAVE.000, has map 3 in its item cache, and the game takes a map from the cache, not from the .DAT files, when the cache holds that map. It was made with map 3 loaded, where the game starts. So when map 3 changes, the editor loads it into the cache again from the files it has just written, and marks no region as loaded, so the game puts the regions around the Avatar down itself.

Writing a map back gives the same bytes it was read from, so a save changes only what was changed.

20. The usecode

Most of the game is usecode: scripts in USECODE/EUSECODE.FLX, in classes. An item runs the class of its shape; a permanent character (NPC slot 1 to 255) runs class 1024 + its number; a usecode egg runs class 1151 + its quality. The engine sends a class events: 0 look, 1 use, 2 anim, 4 cachein, 5 hit, 6 gotHit, 7 hatch, 8 schedule, 10 equip, 11 unequip, 12 combine, 15 and 16 when its area starts and stops running, 19 when the Avatar steals, and others.

The Usecode tab lists every class with code: its number, name, the events it handles, and how many items on the maps run it (filter by number or name). A class's code is shown an instruction a line, the way the interpreter reads it (u8/inter.cpp):

  • each routine starts with a yellow heading: the event it handles, or "routine" and its offset for one that is called (by the class itself or by others);
  • each line has its offset, the instruction and its operands; intrinsic calls give the intrinsic's name (Item::bark, teleportToEgg...), strings are green;
  • branches, calls and spawns are links: follow them to their target, in this class or another;
  • a global flag read or written links to the Flags tab, showing that flag.

Below the listing, Items lists every item on the maps that runs the class (double-click to show one), and Called from the other classes that call or spawn its routines.

The graph

Graph (beside the routine list) shows the routine chosen there as a graph, as IDA draws a function: its instructions in boxes that run straight through, a box ending at each branch or return, joined by arrows to where the code goes next:

  • green: where an if false, go to goes when the value is true (it falls through), and a for each loop's body;
  • red: where it goes when the value is false, and where a loop goes when its list is done;
  • blue: a go to; grey: straight on into the next box.

Arrows that go back up (loops) run round the left of the graph; arrows that skip boxes run round their right. A line that reads a global flag has a red arrow coming in from the left, labelled with the flag (and its name, when it has one in the Flags tab); a line that writes one has a green arrow going out to the right.

Wheel to zoom, drag to move, 0 to fit, 1 for actual size. Double-click a line to follow it: a call or spawn opens that class, a flag the Flags tab, a branch its target box.

The usecode is a stack machine: values are pushed, operations take them off and push their result, [bp-02] is a local variable, and a call's result is read back with "push result" or "push temp". The editor's names for a few rarely used instructions are its own reading of what the interpreter does.
